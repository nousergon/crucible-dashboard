# alpha-engine-dashboard — Dashboard Module

> System architecture, S3 layout, module overview, and cross-repo conventions: see [`~/Development/CLAUDE.md`](../CLAUDE.md). This file covers dashboard-specific operational details only.

## What this repo is

Multi-surface EC2 box (t3.small, 5 systemd services), auto-deploys on merge (~30s push-to-live: GHA OIDC → SSM → `git reset --hard` + `deploy-on-merge.sh` → restart + health-gate every service). Services: `dashboard` :8501 (private Streamlit console at `console.nousergon.ai`, Cloudflare Access), `nous-ergon-live` :8502 (public Streamlit at `live.nousergon.ai`), `crucible-dash` :8504 (Streamlit `/dash` skin, rollback-only since the 9-D cutover), `crucible-dash-api` :8506 (internal FastAPI), `crucible-dash-web` :3002 (Next.js 15/React 19 prosumer surface at `crucible.nousergon.ai/dash`, Cloudflare Access-gated, config#1957/#1973 — implements the Performance/Integrity/About experiment-results framework). **Alpha contribution:** operational visibility — surfaces data for informed manual interventions and (via `/dash`) the experiment-harness results surface.

## Stack

- **Python / Streamlit** (repo root + `live/` + `dash/`): `streamlit>=1.40`, `pandas>=2.0`, `plotly>=5.18`, `boto3>=1.36` (S3 conditional writes for the Morning Signal schedule editor), `pyyaml>=6.0`, `streamlit-calendar>=1.2` (Morning Signal Content Schedule page), `yfinance>=0.2.40` (15-min delayed quote, fail-soft), morning-brief consumer on the Live Portfolio page now routes via OpenRouter `deepseek/deepseek-v4-flash` through `krepis.llm.LLMClient` (`live/morning_brief.py`; the old `anthropic`/`st.secrets` Haiku path was verified live-dead and removed in the I2997 wave — corrected 2026-07-22, see ~/.claude/CLAUDE_CHANGELOG.md), `krepis>=0.10.0` (public PyPI, usage-pacing window math — unrelated to `nousergon-lib`), `nousergon-lib` (git-tag-pinned; `setup_logging`/FlowDoctorHandler, `transparency.substrate_health`, `pipeline_status` SF-state projection).
- **FastAPI** (`dash_api/`): `uvicorn dash_api.main:app`, internal-only on 127.0.0.1:8506, read-only — response shapes documented by `tests/test_dash_api.py` contract tests, mirrored by the Next.js client's fixtures. Fail-loud: a hard loader failure returns 503 with the exception name, never a silent empty 200.
- **Next.js 15 / React 19** (`dash-web/`): TypeScript, Tailwind, Vitest + Testing Library, `recharts`. Talks to `dash_api` via `DASH_API_URL=http://127.0.0.1:8506`. CI job `dash-web` (`.github/workflows/ci.yml`) runs `npm ci` → `npm test` (vitest) → `npm run typecheck` → `npm run build` on every push/PR — a TS or build break can't reach the merge deploy.
- **Nginx** (`infrastructure/nginx.conf`): fronts this box's services AND several sibling repos' — `live.nousergon.ai`/`nousergon.ai` (apex, deprecated, cutting to CF Pages/Astro) → :8502; `console.nousergon.ai`/`dashboard.nousergon.ai` (deprecated alias) → :8501; `/dash` path on the live/apex server block → proxied to :3002 (Next.js, rollback = repoint at :8504 Streamlit skin); `portfolio.nousergon.ai` → :3000 (Metron web, separate repo `cipher813/metron`, Access-gated); `telos-dash.nousergon.ai` → :3001 (Telos, separate repo `nousergon/telos`, Access-gated); `metron-dash.nousergon.ai` → :3003 (Metron `/dash`, separate repo, inert until DNS+service exist). SSL terminated by Cloudflare Origin CA; both private hostnames additionally sit behind Cloudflare Access. Deploy: auto-applied on every push to `main` via `deploy-on-merge.sh`'s nginx-on-diff step (stage → `nginx -t` validate → atomic swap + reload, revert on validation failure).
- **Blog**: static Hugo site built from `blog/` (source tracked, `blog/public/`/`blog/resources/` build output gitignored), served by nginx at `/blog/`.
- **CI** (`.github/workflows/ci.yml`): Python job installs `requirements.txt` + pytest, runs `pytest tests/ -v`, then a non-blocking `pip-audit || true`. Dash-web job as above. `notify-main-failure` pages Telegram only on genuine post-merge breakage of `main` (reusable workflow in `nousergon-lib`) — PR-branch reds stay silent.
- **Deploy** (`.github/workflows/deploy.yml`): triggers on push to `main`. GHA assumes an OIDC role (`github-actions-lambda-deploy`), sends an SSM `AWS-RunShellScript` command to the dashboard EC2 instance (`DASHBOARD_INSTANCE_ID` repo variable) that does `git fetch` + `git reset --hard <GITHUB_SHA>` (pinned to the workflow's own commit, not `origin/main`, to guard against a racing back-to-back merge) then runs `infrastructure/deploy-on-merge.sh <GITHUB_SHA>`. Also idempotently ensures a CloudWatch disk-critical alarm exists (`alpha-engine-dashboard-box-disk-critical`, config#2227) and appends to the system-wide deploy changelog. `boot-pull.sh` remains the daily (12:00 UTC) safety-net for all repos / drift catch — it only restarts services whose `.service` unit file changed, which is the gap `deploy-on-merge.sh` closes for code-only changes.

## Key files

- `app.py` — Streamlit console entry point (`:8501`), a pure triage ROUTER (console-IA phase 3, config#1989): fleet strip + Decision Queue chip, Today's Activity, Key Metrics (NAV/Daily Alpha/Cum Alpha/Hit Rate from `eod_report.json`), System Report Card chips, Regime chip line, Alerts. Wires up `nousergon_lib.logging.setup_logging` at module top for FlowDoctorHandler capture of import-time errors too.
- `live/app.py` + `live/infrastructure/nous-ergon-live.service` — public Streamlit console (`:8502`), `baseUrlPath=live` (all routes incl. health live under `/live`).
- `dash/app.py` + `infrastructure/crucible-dash.service` — Streamlit `/dash` skin (`:8504`, WorkingDirectory=`dash/` so `dash/.streamlit/config.toml` is picked up), same six Crucible Results views (`views/Crucible_*.py`) as the console via the shared `results.view_model` layer. Rollback-only since the Next.js (9-D) cutover; docstring says port 8503 but the deployed systemd unit is 8504 — trust the `.service` file.
- `dash_api/main.py` + `infrastructure/crucible-dash-api.service` — internal FastAPI (`:8506`), read-only results API backing `dash-web`; loaders in `loaders/s3_loader.py` + `loaders/trust_battery_loader.py`, view-model in `results/view_model.py`, `results/battery_registry.py`.
- `dash-web/` + `infrastructure/crucible-dash-web.service` — Next.js prosumer surface (`:3002`, `npm run start`, `After=crucible-dash-api.service`), basePath `/dash`, served publicly at `crucible.nousergon.ai/dash` via the `crucible-live-proxy` Cloudflare Worker.
- `infrastructure/deploy-on-merge.sh` — post-pull deploy script: lib refresh, nginx reload-on-diff, `systemctl restart` for all 5 services, health checks against `/_stcore/health` (console/live/dash Streamlit apps), `/api/health` (dash-api), and `/dash` (dash-web). Its `paths_changed()` helper deliberately avoids `git diff | grep -q` under `pipefail` — SIGPIPE races (config#2242) made that pattern silently report "no change" ~99% of the time on real multi-chunk diffs; captures diff output/exit code directly instead, and treats a `git diff` failure as "assume changed" rather than "assume unchanged."
- `infrastructure/boot-pull.sh` — daily (12:00 UTC) safety-net across all repos on the box; only restarts services whose `.service` unit changed.
- `infrastructure/box_health.sh` / `box_hygiene.sh` — publishes the `AlphaEngine/Box` disk-metric CloudWatch uses for the disk-critical alarm; general box hygiene.
- `infrastructure/nginx.conf` — see Stack section above; also documents the `live.nousergon.ai` apex-cutover sequence and the sunset window for the deprecated `dashboard.nousergon.ai` alias.
- `infrastructure/systemd/` — additional systemd units beyond the 5 primary services (Morning Signal watchdog/bakeoff installers etc. — see individual `install-*.sh` scripts alongside).
- `health_checker.py`, `fleet_status.py`, `trading_calendar.py`, `intraday_live.py` — shared root-level modules consumed by both the console and live apps.
- `views/`, `charts/`, `components/`, `shared/`, `loaders/` — page implementations, chart helpers, shared UI components, and S3/data loaders used across the Streamlit surfaces.
- `flow-doctor.yaml` — repo-root config for the FlowDoctorHandler wired in `app.py`; `exclude_patterns` starts empty by convention, populated only after observing real ERROR-level noise.
- `tests/` — pytest suite (`pytest tests/ -v` in CI), includes `tests/test_dash_api.py` (contract tests for the FastAPI response shapes) and `tests/test_no_secret_environ_reads.py` (guards that secrets are read via `st.secrets`, not `os.environ`).
- `config.yaml.example` / `live/config.yaml.example` — onboarding templates; canonical config source is SSM Parameter Store (`/alpha-engine/dashboard/{config.yaml,live-config.yaml}`), hydrated by `boot-pull.sh`. Real `config.yaml`/`live/config.yaml` are gitignored.
- `marketing/`, `marketing-apex/`, `marketing-dev/`, `marketing-finance/`, `marketing-metron/`, `marketing-telos/`, `marketing-vires/` — separate Astro/CF-Pages marketing site projects colocated in this repo, deployed via `.github/workflows/deploy-marketing.yml` / `marketing-ci.yml` (not part of the dashboard EC2 box's 5 services).
